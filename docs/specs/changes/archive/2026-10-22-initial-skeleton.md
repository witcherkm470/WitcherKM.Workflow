# Начальный каркас WitcherKM.Workflow

## Источник и цель

Запрос пользователя от 2026-10-22: создать отдельный GitHub-репозиторий рядом с Planner, перенести процесс skills/specs и подготовить каркас приложения с DDD, MediatR, Clean Architecture, React и API. Предметные сущности и подробные сценарии не реализовывать.

## Затронутые canonical specs

- `docs/specs/README.md`: назначение и порядок работы.
- `docs/specs/domain/glossary.md`: только известные понятия.
- `docs/specs/application/README.md` и `docs/specs/ui/README.md`: явная граница ещё не согласованного поведения.
- Технические решения фиксируются в `docs/architecture`, не как продуктовые требования.

## Критерии

1. Приватный `witcherkm470/WitcherKM.Workflow` создан и клонирован рядом с Planner.
2. В новом репозитории действуют адаптированные AGENTS.md, skills и поток change → canonical → code → проверки → archive.
3. Solution собирается из Domain, Application, Infrastructure и Api с направлением зависимостей Clean Architecture; MediatR зарегистрирован без предметных обработчиков.
4. React-приложение собирается и обращается к работающему HTTP API через `/api/health`; предметных сущностей, схемы БД и маршрутов нет.
5. README описывает запуск и границы каркаса; пройдены сборка backend, lint/build frontend и локальная HTTP-проверка.

## План проверки

- Проверить `git status`, структуру ссылок и отсутствие предметных типов.
- Выполнить `dotnet build`, `npm run lint`, `npm run build`.
- Запустить API и запросить `GET /api/health`; проверить запрос клиента через Vite.

## Итог

Все критерии выполнены. Репозиторий создан приватным и клонирован рядом с Planner. Перенесены и адаптированы девять skills, AGENTS.md и порядок работы со спецификациями. Четыре .NET-проекта собираются; React-клиент проходит lint/build и показывает ответ настоящего API. Предметные сценарии и сущности не добавлены.

## Проверки

- `dotnet build WitcherKM.Workflow.sln --no-restore`: 4 проекта, 0 предупреждений, 0 ошибок.
- `npm run lint`: успешно.
- `npm run build`: успешно, 16 модулей.
- `GET /api/health` на запущенном API: HTTP 200, `{"status":"ok"}`.
- `GET /api/health` через Vite proxy: тот же ответ; в браузере показано «API доступен».
- Восстановление NuGet выполнено из локального кэша с отключённым аудитом уязвимостей для этой проверки, потому что сеть NuGet в окружении недоступна.
