# Локальный запуск Workflow через Docker

Источник: решение владельца 22 октября 2026 года после обсуждения общего запуска проектов.

## Цель

Запускать Workflow отдельным Docker Compose проектом по образцу Planner, не меняя Planner. Общую конфигурацию в корне RiderProjects пока не создавать.

## Критерии

1. Из репозитория Workflow одной командой собираются и запускаются API и React UI в отдельных контейнерах.
2. UI доступен только с локального компьютера на порту 8081, не занятом Planner; `/api` направляется к API.
3. SQLite и изображения сохраняются в постоянном томе при пересоздании контейнеров.
4. Есть команды проверки сборки, запуска, остановки и просмотра логов; запуск не требует установки .NET или Node.js на компьютер.
5. Изменения не затрагивают Docker-конфигурацию Planner.

## Проверки

Проверить синтаксис Compose, собрать оба образа и проверить HTTP-ответы UI и API, если Docker Engine доступен. Не запускать проверки функциональности Planner.

## Результат

Созданы отдельные образы API и UI, Compose и скрипт запуска. Проверены `docker compose config`, сборка обоих образов, ответы UI и `/api/health` на порту 8081 и сохранение временной категории после перезапуска API-контейнера. Контейнеры Planner остались на порту 8080.
