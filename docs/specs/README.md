# Спецификации WitcherKM.Workflow

Canonical specs описывают согласованное поведение, а не снимок текущего кода. Сейчас подтверждены назначение продукта и технический каркас. Подробные правила цепочек, шагов, вложений, категорий и поиска будут согласовываться отдельными изменениями.

## Карта

- [Domain: словарь](domain/glossary.md) — известные понятия без преждевременных инвариантов.
- [Application](application/README.md) — место для будущих пользовательских сценариев.
- [UI](ui/README.md) — место для будущих страниц и действий.
- [Architecture](../architecture/overview.md) — техническое устройство; [дизайн](../design/frontend.md) — визуальная основа.
- [Открытые вопросы](questions.md) — неразрешённые решения.

## Изменения

Порядок: **change spec → canonical specs → code → проверки**. Один документ в `changes/active` описывает цель, источник, затронутые canonical specs, критерии и проверки. После подтверждения всех критериев он переносится в `changes/archive` с результатами. Незавершённое остаётся active. Архив не является вторым источником требований.

Процедуры: [spec-management](../../.agents/skills/spec-management/SKILL.md) и [implement-change](../../.agents/skills/implement-change/SKILL.md). Не создавай предметные требования из предположений или особенностей каркаса.
