# Обзор архитектуры

## Проекты и зависимости

| Проект | Ответственность |
| --- | --- |
| `WitcherKM.Workflow.Domain` | Категория, агрегат цепочки со шагами, нормализация имён и локальные инварианты. |
| `WitcherKM.Workflow.Application` | MediatR команды и запросы, сценарии и порты хранения. |
| `WitcherKM.Workflow.Infrastructure` | EF Core, миграции SQLite и папка локальных изображений. |
| `WitcherKM.Workflow.Api` | MVC-контроллеры для HTTP-маршрутов, middleware ошибок и composition root. `Program.cs` только настраивает и запускает приложение. |
| `scripts/` | React-клиент через `/api`; стартовая страница — цепочки. |

```text
Api ──→ Application ──→ Domain
 │
 └────→ Infrastructure ──→ Application, Domain
```

Domain не зависит от других проектов. Application не зависит от Infrastructure или Api. Записи идут через MediatR; Infrastructure реализует порты Application. Категория — отдельный агрегат; шаг живёт только в агрегате цепочки.

## Хранение

SQLite создаётся и обновляется миграциями EF Core при запуске. База находится в `src/WitcherKM.Workflow.Api/App_Data/workflow.db` при локальном `dotnet run`, изображения — в соседней папке `App_Data/images`. Папка исключена из Git. При публикации ContentRoot определяет расположение `App_Data`; для сохранения данных эту папку нужно сохранять между обновлениями приложения.

Загружаются PNG, JPEG, GIF или WebP до 10 МБ. Файлы получают случайные имена, маршрут выдачи проверяет формат имени. Для внешних изображений база хранит точный исходный URL и локальный путь; совпадающий URL использует уже сохранённый файл. После удаления последней ссылки из шагов файл и запись соответствия удаляются. Markdown рендерится без сырого HTML, с безопасной обработкой ссылок и подсветкой блоков кода. При неудачной загрузке внешняя ссылка остаётся. Сервер скачивает только изображения по публичным HTTP(S) адресам, с ограничением размера и времени ответа; автоматические редиректы отключены, каждый переход проверяется отдельно.

`GET /api/health` — техническая проверка HTTP-хоста. UI не обращается к базе напрямую. Identity и совместный доступ не входят в личную локальную версию; API следует запускать только в доверенной локальной среде.

## Docker

Workflow запускается отдельным Compose проектом с контейнерами API и Nginx для собранного React UI. Nginx направляет `/api` к API; наружу привязан только `127.0.0.1:8081`. Папка API `App_Data` подключена к постоянному тому, поэтому SQLite и изображения переживают пересоздание контейнеров. Docker-настройки Planner не изменяются.
