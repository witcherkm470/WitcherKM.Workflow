---
name: incremental-implementation
description: Разбивает многошаговое изменение Workflow на небольшие проверяемые срезы; использовать при реализации нескольких связанных сценариев, а не для одиночной правки.
---

Вход — change и релевантные canonical specs из [implement-change](../implement-change/SKILL.md). Выбери минимальный законченный сценарий с наблюдаемым результатом, затем зависимости и следующий срез. Рискованный неизвестный контракт проверь первым.

Для каждого среза: требование → регрессионная проверка → реализация → [testing](../testing/SKILL.md) → сверка результата. При поломке зависимого пути используй [debugging-and-error-recovery](../debugging-and-error-recovery/SKILL.md), прежде чем строить на нём следующий срез.

Не дроби работу только по слоям, оставляя пользовательский сценарий неработоспособным. Не вводи флаги, новые абстракции или соседний refactoring без потребности текущего изменения. Срез должен быть понятен в diff; commit/push выполняются в пределах запроса пользователя.

Выход — работающий срез, результаты релевантных проверок и оставшиеся критерии change. Успешные проверки неизменённого кода не повторяй без причины.
